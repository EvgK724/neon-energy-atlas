# Обслуживание атласа

Приложение: https://evgk724.github.io/neon-energy-atlas/ . Репозиторий EvgK724/neon-energy-atlas, main, каталог docs. Сохранять текущий адрес, дизайн и определения метрик. Пользователь разрешил обновление данных/прогнозов, публикацию и push о значимых изменениях; платные сервисы не подключать.

## Планировщик

`.github/workflows/atlas.yml`: Sunday 05:00 UTC, с проверкой интервала 14 дней от 2026-10-25. На промежуточной неделе источники не опрашиваются и публикация не производится. Это облачное задание GitHub Actions, не задача ChatGPT Work. Cloud Work вернул `not available for this account`; создавать дублирующие локальные автоматизации нельзя. Запуск вручную: workflow_dispatch → refresh=true.

## Каждый цикл

1. `python3 scripts/update_data.py --write`: PRIS, Ember, GSMA, OpenDatacenterMap. Ошибка одного источника сохраняет его прежние данные и retrieval date. Не снижать пороги проверок ради успешного запуска. Не обходить 403/429.
2. `python3 scripts/monitor_forecasts.py`: проверка доступных первичных HTML-источников. Скрипт не исследовательская AI-задача. Он не подменяет проверенные сценарии непроверенными числами; блокировки/PDF видны в метаданных. При ручном исследовательском цикле проверить новые выпуски IEA/IAEA, государственные программы и космические проекты; не ограничиваться старыми URL. Проверенные новые forecasts импортируются через `update_data.py --forecasts FILE --write`. Удаление/замена сценария требует объяснения в журнале.
3. `python3 scripts/test_data.py`, `node scripts/test_metrics.cjs`; для изменения UI — `node scripts/verify.cjs URL` в Chromium и WebKit.
4. `python3 scripts/build.py`. Коммитить JSON, журнал, forecast-watch, service worker и version. GitHub Pages публикуется самим workflow: коммит GITHUB_TOKEN сам по себе не запускает Pages.
5. После deploy проверить публичный data revision. Частично не обновившийся источник оставляет run failed после публикации исправных данных; сбой не маскируется нулями.

Ember читается из постоянно обновляемой официальной CSV, со строгой проверкой схемы. Новые годы GSMA обнаруживаются в официальном каталоге; смена определения показателя требует сверки. Старый год остаётся явно указанным до появления нового сопоставимого источника. Мир — отдельный итог источника; не складывать страны разных лет. OSM country sum + dcUnassigned = world.dc. PRIS суммы всех стран = мировой счётчик.

## Значимые изменения

ЦОД: >=5% и >=5 объектов; выработка: >=3%; действующие или строящиеся блоки: >=1; 5G: >=5 п.п.; проверенный прогноз: >=10% при том же горизонте либо сдвиг года >=1/новый сценарий. Нули, пропуски, изменение базы/методики обрабатываются отдельно. Существенное изменение OSM может отражать пополнение карты, а не строительство.

`docs/data/alerts.json`: schema=1, events с уникальными id, publishedAt ISO UTC, title, body. Нельзя включать секреты, подписки или персональные сведения. Push body не длиннее 700 символов. `countries.json.changes` содержит подробности/ссылки. Для источника прогноза сообщение об изменении числового текста — запрос сверки, не утверждение о подтверждённом новом сценарии.

## Push-сервер

Supabase project `wgkifqdgdvwfyvbzwytv`, free, Frankfurt. Функция `atlas-push`, исходник `server/push/index.ts`. Доступ к устройству — случайный 256-bit capability из установки (на сервере только SHA-256); читать другие устройства нельзя. Подписки, закрытый VAPID и административный токен недоступны anon/authenticated (RLS + REVOKE). Публичные данные — URL и открытый VAPID в push-config.json.

GET функции — health/public key. POST subscribe/test/unsubscribe требует разрешённого Origin и capability установки. Произвольные URL подписок отклоняются: только официальные Web Push провайдеры Apple/Google/Mozilla, HTTPS. deliver требует серверного административного токена; берёт данные только из фиксированного публичного feed, не из тела запроса. До доставки отбрасываются события старше 30 суток/создания подписки, повторные ID не отправляются. Истёкшие 404/410 подписки удаляются.

Задание pg_cron `atlas-push-delivery` каждые 10 минут вызывает Edge Function через pg_net; секрет читается из закрытой таблицы внутри SQL и не возвращается в вывод. Не публиковать admin_token, vapid_private или содержимое subscriptions. Проверка состояния — только количество устройств, active/schedule, HTTP status и агрегаты sent/failed. Бесплатный проект может приостанавливаться при неактивности; не переходить на платный тариф. Запрос пользователя на включение push не заменяет разрешение iOS — пользователь нажимает кнопку на каждом устройстве.

## Новые темы

В тот же 14-дневный цикл включены EIA (добыча нефти), USGS (добыча и запасы золота), GCAT (пуски и спутники) и официальный JSON доступности Starlink. GitHub Actions устанавливает `pypdf==6.10.0` при обновлении. До применения проверяются единицы, периоды, дубликаты, размер таблиц и мировые итоги. Добыча и запасы золота применяются совместно после проверки обеих колонок. Новый год USGS проверяется после смены календарного года; ошибка или несовпадение редакции сохраняет прежние значения.

EIA использует бесплатный публичный DEMO_KEY. Ошибку лимитирования нельзя маскировать старой bulk-выгрузкой с другой датой. `--only eia|usgs|gcat|starlink` позволяет проверить отдельный новый адаптер. Параметр `--write` разрешает запись; без него создаётся только локальный отчёт проверки.

OGJ (выборка 15 стран), нижняя граница iPhone и отчёт об абонентских линиях Starlink — проверенные публикации. Автоматическая замена чисел без сверки нового выпуска не настроена. Не объявлять их обновляемыми при каждом цикле. Всегда сохранять дату, определение, ограниченный охват и знак `>` у iPhone. OPEC и OGJ не взаимозаменяемы: учёт газовых жидкостей и нефтяных песков различается.

Дополнительные пороги: добыча и запасы ресурсов — 5%; пуски — 10% и 3 попытки (полный и неполный год раздельно); спутники страны — 5% и 10 аппаратов; Starlink на орбите — 5% и 100 аппаратов; смена доступности услуги Starlink; новая сверенная оценка iPhone — 10%. Сброс YTD в январе не является падением пусковой активности. Пропуск в предыдущем снимке не считается нулём. Пуш и журнал округляют видимые числа до десятых, исходные изменения сохраняют полную точность.

После изменения интерфейса запускать также `node scripts/verify_topics.cjs URL`. Этот набор проверяет новые слои и рейтинги, одновременное включение всех 12 слоёв, сохранение выбора, особый статус Starlink и знак нижней границы iPhone на узких экранах с текстом 150%.
